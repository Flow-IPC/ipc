40/**
41 * Returns the process-global mutex serializing any mutation of jemalloc's arena set (arena create/destroy)
42 * against a whole-arena-set statistics dump (jemalloc `malloc_stats_print()`), so that the two never overlap.
43 *
44 * ### Why this exists ###
45 * `malloc_stats_print()` walks every arena unguarded: it first caches which arenas are `initialized`, then reads
46 * each arena's `"stats.*"`; if an arena is *destroyed* (from any thread) in that window, the per-arena read fails
47 * and jemalloc *aborts the process* (its internal `xmallctlbymib()` is an abort-on-error wrapper). This is not a
48 * jemalloc bug -- the full dump assumes a quiescent arena set. Holding this mutex around (1) each arena-destroy,
49 * (2) each arena-create, and (3) each such dump makes that assumption hold.
50 *
51 * @note There might be other global-arena-list-touching ops out there in universe; if so they should probably
52 * be bracketed with this lock too.
53 *
54 * An unguarded stats-dump happening at a bad time, sans this mutex, tends to sporadically abort with
55 * a message like `<jemalloc>: Failure in xmallctlbymib()` and variations (always with `<jemalloc>: ` prefix
56 * at least).
57 *
58 * The single-arena, return-checked stat-queries in Ipc_arena::memory_manager_stats() do *not* need this (they touch
59 * only their own live arena and check errors instead of aborting); this mutex concerns exclusively the whole-set dump
60 * versus arena-set mutation. (A different concern -- stats reads by Flow-IPC tearing each other -- is handled by
61 * jemalloc_stats_mutex().)
62 *
63 * ### Lifetime ###
64 * The returned mutex is intentionally immortal (never destroyed): it is locked at "touchy" times -- past `main()`
65 * and during thread exit, where the arena-destroy path might run -- at which point a destructible function-local
66 * `static` could already have been destroyed.
67 *
68 * ### Locking discipline ###
69 * Treat it as a leaf: acquire it only immediately around the single jemalloc call (destroy/create/dump) and hold
70 * no other lock while it is held.
71 *
72 * @return Reference to the immortal process-global mutex.
73 */
74flow::util::Mutex_non_recursive& jemalloc_arena_list_mutex();

76/**
77 * Returns the process-global mutex held throughout each of Flow-IPC's jemalloc-statistics operations --
78 * Ipc_arena::memory_manager_stats(), Ipc_arena::memory_manager_stats_reset(), and the whole-arena-set stats dumps
79 * (`Memory_manager::...stats_dump...()`) -- so that no two of them overlap.
80 *
81 * ### Why this exists ###
82 * Each of those operations refreshes jemalloc's stats snapshot and then reads many (hundreds or more) values from
83 * it, one by one. There is one such snapshot for the entire process (see stat::epoch_refresh()), and any refresh
84 * replaces it. Without this mutex, Flow-IPC's own stats operations -- e.g., the periodic ones `ipc::session` runs
85 * for each `Ipc_arena` it sets up -- would refresh in the middle of each other's reads. Moreover, as each read
86 * separately takes jemalloc's internal stats lock, they would slow each other down. Ipc_arena does detect a
87 * mid-read refresh and read again; but with enough such contention, the re-reads can keep failing indefinitely
88 * (observed in testing).
89 *
90 * What a mid-read refresh does, if undetected: the reads are "torn," mixing values from different moments. Derived
91 * results can then be nonsense: e.g., more deallocations than allocations, so a computed (unsigned) live-count
92 * underflows to a huge number -- which also becomes its high-water mark until the next reset.
93 *
94 * Code outside Flow-IPC using jemalloc stats APIs directly is not excluded by this mutex. Ipc_arena detects and
95 * retries those (Ipc_arena::memory_manager_snapshot_read()). A dump cannot (jemalloc's `malloc_stats_print()`
96 * refreshes once, then reads); such a dump merely prints some mutually inconsistent numbers.
97 *
98 * ### Also: Ipc_arena reset-baseline ###
99 * Because it is held throughout each Ipc_arena stats operation, this mutex also protects that Ipc_arena's
100 * reset-baseline (`Ipc_arena::m_mem_mgr_base_stats`) and thus makes Ipc_arena::memory_manager_stats() and
101 * Ipc_arena::memory_manager_stats_reset() safe to call concurrently. See there.
102 *
103 * ### Lifetime ###
104 * Immortal (never destroyed), like jemalloc_arena_list_mutex(), so that it is safely usable at any time.
105 *
106 * ### Locking discipline ###
107 * Lock order: this; then jemalloc_arena_list_mutex() (if applicable), which remains a leaf.
108 *
109 * @return Reference to the immortal process-global mutex.
110 */
111flow::util::Mutex_non_recursive& jemalloc_stats_mutex();

150/**
151 * Refreshes jemalloc's statistics snapshot (writes `mallctl("epoch")`), so that subsequently-read `"stats.*"`
152 * values reflect the present; and returns the epoch of the resulting snapshot.
153 *
154 * ### Background: jemalloc's stats snapshot and `epoch` ###
155 * jemalloc does not compute a `"stats.*"` value when it is read; it serves every such read from one stored
156 * snapshot. A refresh (writing any value to `epoch`) copies every arena's current counters into that snapshot
157 * and increments a counter, the *epoch*. Merely reading `epoch` (epoch()) refreshes nothing. `man` page wording
158 * (the `epoch` entry): "If a value is passed in, refresh the data from which the `mallctl*()` functions report
159 * values, and increment the epoch. Return the current epoch. This is useful for detecting whether another
160 * thread caused a refresh."
161 *
162 * There is one snapshot, and one epoch, for the entire process. So a refresh by anyone in the process (another
163 * `Ipc_arena` reading its stats; a stats dump; any code using jemalloc directly) replaces what everyone reads
164 * next. Each individual `"stats.*"` read is coherent; but a refresh between 2 reads of a batch
165 * makes the batch "torn": values from different moments. That can corrupt derived quantities (e.g., live-count =
166 * `nmalloc - ndalloc` can underflow). Conversely, with no refresh at all, reads are stale: frozen at the last
167 * snapshot, or all-zero if none was ever taken.
168 *
169 * Recipe for a consistent batch: `e = epoch_refresh()`; read the batch; if `epoch() != e`, someone refreshed
170 * mid-batch, so set `e = epoch()` and read the batch again. There is no need to refresh again on such a retry:
171 * the other party's refresh already produced a snapshot at least as new as ours. Moreover, if we did refresh
172 * again, 2 concurrent readers could keep tearing each other's batches indefinitely.
173 *
174 * @return The epoch of the snapshot just taken.
175 */
176uint64_t epoch_refresh();

186/**
187 * Resolves a `mallctl` name -- which may contain integer components (e.g. the `0`s in
188 * `stats.arenas.0.bins.0.nmalloc`) -- to its Management Information Base (MIB), enabling repeated reads via
189 * mallctl_read_mib() without repeated name lookups. Per the jemalloc MIB convention the integer components
190 * become fixed MIB slots that the caller may mutate per iteration (e.g. set the arena-index slot to each JAID).
191 *
192 * @param name
193 * The (NUL-terminated) `mallctl` name to resolve.
194 * @param mib
195 * Buffer receiving the resolved MIB; must have capacity for at least `*mib_len` components.
196 * @param mib_len
197 * In: the capacity of `mib` (the name's component count, e.g. 6 for `stats.arenas.0.bins.0.nmalloc`).
198 * Out: the actual resolved MIB length.
199 * @return `true` on success; `false` on any `mallctl` error.
200 */
201bool mallctl_name_to_mib(const char* name, size_t* mib, size_t* mib_len);

203/**
204 * Reads a single scalar `mallctl` value, by name, into `*val` (using `sizeof(T)` as the value size). Intended
205 * for one-off reads (init-time constants, scalars); for repeated reads of an indexed path prefer
206 * mallctl_name_to_mib() + mallctl_read_mib().
207 *
208 * @tparam T
209 * The scalar type of the value as dictated by jemalloc for `name` (e.g. `size_t` for byte gauges,
210 * `uint64_t` for cumulative counters, `bool` for `"config.*"`). A wrong-sized type yields failure
211 * (jemalloc requires an exact size match).
212 * @param name
213 * The (NUL-terminated) `mallctl` name to read.
214 * @param val
215 * On success, set to the read value; untouched on failure.
216 * @return The `mallctl()` result: 0 on success; else the (`errno`-style) error (e.g. `ENOENT` if `name` is
217 * unavailable in this build).
218 */
219template<typename T>
220int mallctl_read(const char* name, T* val);

222/**

230 * @param mib_len

234 * @return See mallctl_read().

239/**
240 * Computes, for the given jemalloc-arena, the cumulative bytes-ever-allocated and bytes-ever-deallocated (by
241 * summing each per-size-class cumulative op-count times that size-class's byte-size), and populates a
242 * by-size-class allocation-count histogram spanning all classes (jemalloc's small `bins` then its large
243 * `lextents`, concatenated) -- all in one walk over the per-size-class counters. jemalloc has no direct
244 * cumulative-bytes counter: hence the aforementioned derivation.
245 *
246 * The histogram, with its request-range bucket bounds (see the by-size histogram member docs in
247 * arena_lend_stats.hpp), is (re)constructed fresh, then its buckets are overwritten from `nmalloc`
248 * (region allocations). So it is an ACCUMULATOR (with N per-bucket counts) in the
249 * `flow::util::stat::Stat_type` sense.
250 *
251 * Pre-conditions: jemalloc-stats enabled within jemalloc; jemalloc-stats epoch refreshed.
252 *
253 * @param arena_id
254 * The jemalloc-arena to read.
255 * @param alloc_sz
256 * Out: cumulative bytes allocated. Must not be null.
257 * @param dealloc_sz
258 * Out: cumulative bytes deallocated. Must not be null.
259 * @param alloc_count_by_size
260 * Out: by-size-class cumulative alloc-count histogram (from `nmalloc`; overwritten). Must not be null.
261 */
262void cumulative_alloc_dealloc_sz(arena_id_t arena_id, uint64_t* alloc_sz, uint64_t* dealloc_sz,
263 flow::util::stat::Histogram_counter* alloc_count_by_size);
