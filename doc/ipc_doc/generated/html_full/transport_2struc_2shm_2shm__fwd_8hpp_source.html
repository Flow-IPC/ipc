28/**
29 * Segregates zero-copy/SHM implementations of concepts residing in parent namespace ipc::transport::struc proper --
30 * most notably the concepts ipc::transport::struc::Struct_builder and ipc::transport::struc::Struct_reader --
31 * and items related to them. This namespace proper is focused on struc::shm::Builder and struc::shm::Reader,
32 * templates which enable (in a SHM-provider-parameterized way) zero-copyable structured messages by implementing
33 * the aforementioned pair of concepts respectively.
34 *
35 * @see The guided Manual chapters @ref chan_struct and @ref chan_struct_advanced cover zero-copy structured transport.
36 *
37 * Sub-namespaces, including struc::shm::classic and struc::shm::arena_lend::jemalloc as of this writing,
38 * pertain to SHM-provider-specific items relevant (at least) to that pair of templates (`Builder` and `Reader`).
39 * In particular, e.g., struc::shm::classic::Builder is the concrete type that implements
40 * a zero-copy `Struct_builder` using the ipc::shm::classic SHM-provider (and similarly for `Reader`). For user
41 * convenience and generic coding ease, each SHM-provider shall provide that pair of aliases (`Builder` and `Reader`)
42 * in a sub-namespace in some reasonable way mirroring the SHM-provider core's namespace path. (Hence note that
43 * SHM-classic provider core is in ipc::shm::classic, hence the `Builder` and `Reader` aliases are in
44 * ipc::transport::struc::shm::classic accordingly.)
45 *
46 * (If that didn't read like some sort of comprehensible English, you probably need not worry about it. In particular
47 * if you use ipc::session to set up your IPC, you'll have access to higher-level aliases to make it all simple --
48 * while internally they'll most likely use the stuff in the preceding paragraph. E.g.,
49 * ipc::session::shm::classic::Session_mv::Structured_channel is your guy... no `Builder`s or `Reader`s in sight
50 * about which you would need to worry.)
51 */

72/**
73 * Utility that saves the result of a `Shm_session1::lend_object<T>(const shared_ptr<T>&)` into
74 * the given capnp-generated struct's `shmHandleSerialization :Data` field -- typically a `ShmHandle`-typed field
75 * in your schema. On the deserializing end, one
76 * can get back this value via capnp_get_shm_handle_to_borrow() and pass it to
77 * `Shm_session2::borrow_object<T>()` to yield a `shared_ptr<T>` equivalent to the original passed to `lend_object()`.
78 *
79 * `Shm_session1` and `Shm_session2` supported, respectively, include:
80 * - shm::classic::Pool_arena, shm::classic::Pool_arena (sic);
81 * - session::shm::arena_lend::jemalloc::Shm_session, session::shm::arena_lend::jemalloc::Shm_session (sic);
82 * - session::shm::classic::Client_session, session::shm::classic::Server_session;
83 * - vice versa;
84 * - session::shm::arena_lend::jemalloc::Client_session, session::shm::arena_lend::jemalloc::Server_session;
85 * - vice versa;
86 * - shm::Builder::Session pointee, shm::Reader::Session pointee.
87 *
88 * It is fine to call this repeatedly on the same `*shm_handle_root` (e.g., when re-sending the same message):
89 * the already-allocated `Data` is reused rather than orphaned (capnp `initX()` does not reuse space).
90 *
91 * @tparam Capnp_root_builder
92 * Capnp-generated `X::Builder`, where `struct X` declares field `shmHandleSerialization :Data`.
93 * The typical one is `schema::ShmHandle::Builder`, `ShmHandle` being the public convenience type for
94 * this purpose; but any struct with such a field works (Flow-IPC internally uses this on certain hot-path
95 * header structs, where the field sits directly among other fields, saving a level of nesting).
96 * @param shm_handle_root
97 * Non-null (or behavior undefined/assertion may trip) pointer to builder to mutate.
98 * @param lend_result
99 * What `lend_object<T>()` returned. Not `.empty()`, or behavior undefined (assertion may trip).
100 * Reminder: if that returned `.empty()`, the session is likely hosed, and you cannot transmit SHM objects
101 * between the two endpoints, so there is no point in calling us.
102 */
103template<typename Capnp_root_builder>
104void capnp_set_lent_shm_handle(Capnp_root_builder* shm_handle_root,
105 const flow::util::Blob_sans_log_context& lend_result);
106
107/**
108 * Utility that's the reverse of capnp_set_lent_shm_handle() to be invoked on the deserializing side.
109 *
110 * @tparam Capnp_root_reader
111 * Capnp-generated `X::Reader` counterpart to the `Capnp_root_builder` given to capnp_set_lent_shm_handle().
112 * @param shm_handle_root
113 * Reader to access. Behavior undefined if was not set by capnp_set_lent_shm_handle().
114 * @param arg_to_borrow
115 * Shall be set to what to pass to `borrow_object<T>()` (non-null pointer or behavior undefined/assertion
116 * may trip). `arg_to_borrow->get_logger()` shall not be modified; so set it to what you want, if you want.
117 */
118template<typename Capnp_root_reader>
119void capnp_get_shm_handle_to_borrow(const Capnp_root_reader& shm_handle_root,
120 flow::util::Blob_sans_log_context* arg_to_borrow);

237/**
238 * Grabs a snapshot of *everything in serializer global-land* -- for the given SHM-provider `Arena` -- into
239 * `*target_info_dump` which can then be read/printed/aggregated at leisure. That is (see Serializer_info_dump):
240 * the pure-heap, SHM-msg-outer, and SHM-msg-core global serializer stat-sets (3 singletons).

247 *
248 * @tparam Arena
