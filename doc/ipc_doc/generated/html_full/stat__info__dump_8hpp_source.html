39/**
40 * Printable (with knobs in contained util::stat::Info_dump_format) bundling of stats/info relevant to (but not
41 * all necessarily owned by) a particular jemalloc::Ipc_arena as stat-consumed at a particular point in time.
42 * - Stats/info stored by-value; can be queried in peace.
43 * - Can be printed to an `ostream` via `ostream<<`. #m_fmt (`Info_dump_format`) has output-format knobs,
44 * adjusting which ahead of the `<<` will affect the output.
45 * - As usual: can `FLOW_LOG_...(x)` it, `boost::lexical_cast<string>(x)` it, `flow::util::ostream_op_string(x)`,
46 * where `x` is a `*this`.
47 *
48 * ### Subject matter ###
49 * One fills-out the payload by calling `arena.info_dump(&x)`, where `arena` is an `Ipc_arena`; `x` is a `*this`.
50 *
51 * Some of the items saved in a `*this` were (pre-copying-them-into-`*this`) owned by/pertaining to the
52 * specific target Ipc_arena `arena`. (E.g.: #m_sharded_stats.)
53 *
54 * Others (e.g.: #m_owner_pool_lookup_global_stats) are global -- not pertaining to any particular arena -- but
55 * pertain to SHM-arena(s) in general, at least tangentially. Such entities are a/k/a *owner-side*. So they
56 * pertain to `Ipc_arena`s in at least some sense... just not necessarily to *the* arena `arena` that filled `*this`.
57 *
58 * The non-per-`Ipc_arena` data in `*this` may be redundant w/r/t the non-per-`Ipc_arena` data in `*that`.
59 * It is still included simply out of the pragmatic belief that, if one is interested about "everything"
60 * about arena X, they'll want to know about data/algorithms that make arena X (...but also other arenas)
61 * work properly. I.e.: the more the merrier.
62 *
63 * @see The other, disjoint such bundling in SHM-jemalloc is Shm_session_info_dump
64 * (<=> session::shm::arena_lend::jemalloc::Shm_session); it is generally *borrower-side* info.
65 * (Arena_info_dump (<=> jemalloc::Ipc_arena) is SHM-jemalloc's *owner-side* info.)
66 */
67struct Arena_info_dump
68{
69 // Data.
70
71 /**
72 * Print-format knobs in effect at `ostream << *this` time.
73 *
74 * @note Info_dump_format::m_verbose specifically controls whether -- if available in the first
75 * place -- #m_mem_mgr_stats_dump (as from jemalloc::Memory_manager::stats_dump_to_ostream())
76 * shall be included in the output (`true` <=> yes). Additionally if `false` at Ipc_arena::info_dump()
77 * call, then #m_mem_mgr_stats_dump is not generated (empty string saved). However:
78 * @note Info_dump_format::m_multiline being `false` shall cause printing as-if `m_verbose == false`
79 * regardless of its actual value. (It is not reasonable to print jemalloc's huge #m_mem_mgr_stats_dump,
80 * if newlines are not allowed.) `m_multiline` does not affect `info_dump()` generating/saving or not
81 * generating/saving the dump (only `m_verbose` is consulted for that).
82 */
83 util::stat::Info_dump_format m_fmt;
84
85 /// If unavailable then empty; otherwise the newline-terminated output of Memory_manager::stats_dump_to_ostream().
86 std::string m_mem_mgr_stats_dump;
87
88 /// Target `Ipc_arena`'s stats from: Ipc_arena::memory_manager_stats().
89 std::vector<arena_lend::stat::Memory_manager_stats> m_mem_mgr_stats;

103 /// Target `Ipc_arena`'s info from: Ipc_arena::shm_pool_live_info().
104 std::vector<arena_lend::stat::Shm_pool_info> m_shm_pool_live_info;
105}; // struct Arena_info_dump

127 * @see The other, disjoint such bundling in SHM-jemalloc is Arena_info_dump (<=> jemalloc::Ipc_arena);

129 * is SHM-jemalloc's *borrower-side* info.)
