68/**
69 * ~Simplest possible impl of Struct_builder concept that represents the capnp payload directly in heap memory
70 * (outer serialization only), with a segment-allocation strategy similar to `capnp::MallocMessageBuilder`. The
71 * `Struct_builder`-required seg 1 header-space minutiae are also followed.
72 *
73 * That is, each mutation via payload_msg_builder() may, as needed, trigger a `malloc()` (or similar) of size N,
74 * where N is (roughly speaking) either a fixed, configured value; or grows roughly exponentially each time up to
75 * N. (`capnp::MallocMessageBuilder` has similar knobs.) Plus seg 1 shall be preceded by
76 * a (zero-filled, untouched further by `*this`) header area of a specified size if so configured.
77 *
78 * @note This can/should be viewed as the core impl of Struct_builder concept. Other impls thereof most likely
79 * should be built on top of/around a Heap_fixed_builder which would implement the outer serialization, an
80 * element in practice required in a uniform way by any Struct_builder. For example shm::Builder does so: it
81 * maintains a Heap_fixed_builder for the outer serialization (even though in its case it's always one small
82 * segment, certainly without any splitting/joining needed) while itself handling the inner serialization
83 * in SHM.
84 *
85 * @internal
86 *
87 * ### Implementation ###
88 * If one is familiar with capnp, then one can probably quickly guess how this class template accomplishes
89 * what it promises in just the brief summary at the top of this doc header:
90 * Heap_fixed_builder_capnp_message_builder is what we use internally; it's like `MallocMessageBuilder`
91 * but has support for a framing prefix coexisting within at least the first allocated buffer/segment. As it must, that
92 * builder (like `MallocMessageBuilder`) is documented to allocate a larger-than-N segment if necessary to encode a
93 * particular too-large leaf. We do not stop this in and of itself; but emit_serialization() -- if supplied
94 * a split_segs out-arg -- will emit sub-segments in split fashion where needed. (If `split_segs` is null, then
95 * per concept requirements emit_serialization() will emit an error and barf, if a particular segment is too large.)
96 *
97 * @endinternal
98 *
99 * @see Heap_reader
100 * Counterpart Struct_reader implementation that can deserialize data that this has serialized.
101 * @see Struct_builder: implemented concept.
102 */
103class Heap_fixed_builder :
104 public flow::log::Log_context

106public:
107 // Types.

109 /**
110 * Implements Struct_builder::Config sub-concept. In particular, since this is the core outer-serialization
111 * Struct_builder impl -- used either by itself or (realistically) in any other impl for its mandated
112 * outer-serialization aspect -- it takes most of its members directly from the concept description.
113 * Namely: #m_frame_prefix_sz; and (since indeed Heap_fixed_builder *can* produce non-small segments)
114 * #m_seg_and_frame_sz_cap. The latter is the max size of each segment (emit_serialization() will split any
115 * segment if it was forced to make a larger one). Lastly there is #m_segment_sz_init which is first (ideally
116 * only) segment's size.
117 *
118 * @note If `m_segment_sz_init == m_seg_and_frame_sz_cap` (ignoring `m_frame_prefix_sz` for simplicity of exposition),
119 * then subsequent segments cannot grow any further (the cap is already reached). This is in effect
120 * how `MallocMessageBuilder`'s `FIXED_SIZE` strategy acts, whereas if `m_segment_sz_init` is smaller, then
121 * we work like `GROW_HEURISTICALLY` strategy instead.
122 *
123 * @note Heap_fixed_builder_capnp_message_builder is internally used. It implements `capnp::MessageBuilder` much as
124 * capnp's out-of-the-box `MallocMessageBuilder` does. We mention this in case you needed a `MessageBuilder`
125 * directly for whatever reason.
126 */

129 // Types.
130
131 /// Implements concept API.
132 using Builder = Heap_fixed_builder;
133
134 // Data.
135
136 /// Logger to use for logging subsequently.
137 flow::log::Logger* m_logger_ptr;
138
139 /**
140 * Cap for how large a buffer size to choose for any header+segment buffer. The header size is controlled
141 * by #m_frame_prefix_sz; and is that value for seg 1 but zero for all subsequent ones.
142 *
143 * ### capnp behavior discussion ###
144 * Let N be this value minus the header size for that segment (so `m_frame_prefix_sz` or 0).
145 * Per capnp rules, a given segment may still exceed N, namely if capnp asks -- when calling
146 * `capnp::MessageBuilder::allocateSegment()` API -- for a value exceeding N. This occurs if and only if a
147 * particular capnp-leaf, probably a list/blob/string, is by itself of that size; a leaf can't be split across
148 * segments.
149 */
150 size_t m_seg_and_frame_sz_cap;
151
152 /**
153 * Seg 1 size; a value exceeding `m_seg_and_frame_sz_cap - m_frame_prefix_sz` is clamped to that.
154 *
155 * ### capnp behavior discussion ###
156 * capnp will request a segment 1 of size ~0 regardless of how the user acts; as I (ygoldfel) recall before even any
157 * capnp-generated mutators are called by the user. Therefore seg 1 shall be sized according to this value
158 * (as the larger of ~0 and X is X; in this case X being `m_seg_and_frame_sz_cap - m_frame_prefix_sz`);
159 * it doesn't matter what the first leaf the user adds to the message. Subsequent `allocateSegment()` calls,
160 * however, will actually be based on what the capnp-user needs from that point on.
161 *
162 * The point here is that seg 1 has a known, certain size, which is a nice thing to be deterministic about;
163 * after that it depends. In particular if `m_seg_and_frame_sz_cap - m_frame_prefix_sz` is sufficient for
164 * the entire message, then that's it.
165 *
166 * Therefore it is important for efficiency to select a nice `m_segment_sz_init` that's larger (ideally) than
167 * what is ultimately necessary for the whole message but doesn't leave too much slack. Zero-filling allocations
168 * are fairly expensive (that is to say, `calloc(N)` is more expensive than `calloc(M)`, where N > M).
169 */
170 size_t m_segment_sz_init;
171
172 /**
173 * Size of header to precede seg 1 in the first buffer allocated by the Heap_fixed_builder. The size must
174 * be alignment-friendly (per align-size `sizeof(capnp::word)`). Zero is allowed.
175 *
176 * No segment after seg 1 shall be preceded by such a header.
177 */
178 size_t m_frame_prefix_sz;
179
180 /**
181 * See Struct_builder::Config concept. Pointee (null OK = no stats kept) for cumulative
182 * snd-stats; must outlive each Heap_fixed_builder built with `*this`.
183 */
184 stat::Serializer_stats::Snd* m_stats;

491template<typename Struct>
492typename Struct::Reader Heap_reader::deserialization(const Split_segments* split_segs_or_null, Error_code* err_code)
493{
494 using flow::error::Runtime_error;
495 using flow::util::buffers_dump_string;
496 using flow::util::stat::fetch_add;
497 using flow::util::stat::update_hi_wmark;
498 using boost::movelib::make_unique;
499 using std::vector;
500 using std::swap; // Required for correct ADL-semantics.
501 using ::capnp::word;
502 using Capnp_word_array_array_ptr = kj::ArrayPtr<const Capnp_word_array_ptr>;
503 using Capnp_heap_engine_opts = ::capnp::ReaderOptions;
504
505 FLOW_ERROR_EXEC_AND_THROW_ON_ERROR(typename Struct::Reader, deserialization<Struct>, split_segs_or_null, _1);
506 // ^-- Call ourselves and return if err_code is null. If got to present line, err_code is not null.
507
508 // See explanation and associated to-do in shm::Reader::deserialization(); applies equally here.
509 constexpr Capnp_heap_engine_opts RDR_OPTIONS = { std::numeric_limits<uint64_t>::max() / sizeof(word),
510 Capnp_heap_engine_opts{}.nestingLimit };
511
512 if (m_serialization_segments.empty())
513 {
514 *err_code = error::Code::S_DESERIALIZE_FAILED_INSUFFICIENT_SEGMENTS;
515 return {};
516 }
517 // else: OK so far.
518
519 assert((!m_engine) && "Do not call deserialization() more than once.");
520
521 if (split_segs_or_null) // Note: This being true is rare, or should be; which is good, as reassembly is costly.
522 {
523 const auto& split_segs = *split_segs_or_null;
524 if (split_segs.empty())
525 {
526 FLOW_LOG_WARNING("Heap_reader [" << *this << "]: "
527 "Split-segment records sequence is supplied but empty, against internal protocol; "
528 "it should have not been supplied (null).");
529 *err_code = error::Code::S_DESERIALIZE_FAILED_REASSEMBLY_FAILED;
530 return {};
531 }
532 // else
533
534 /* Time to reassemble the segments, as needed, according to split_segs if not null. split_segs semantics are
535 * simple, but please refer to the doc header of Split_segments for a recap. Per the algorithm explained there,
536 * scan through split_segs in backwards order (so as to avoid making later-scanned indices in split_segs become
537 * wrong), and join each sequence of 2+ elements of m_serialization_segments (as described in that split_segs[])
538 * into 1, in-place. A couple of subtleties to point out ahead of time:
539 * - It is possible (we won't discuss here how likely; it depends on stuff not in our purview, but trust me that
540 * it is at least conceivably possible) that when we must join 2+ segs, in order, [s1, ...], the area
541 * [s1.begin() + s1.size(), s1.begin() - s1.start() + s1.capacity()) (the unused, but allocated, area in the
542 * first of the to-be-joined sub-segments) is large enough to hold the combined `.size()`s of the remaining ...
543 * sub-segments. In that case, for perf, we reuse s1 as the ultimately-joined segment Blob, copying each of ...
544 * onto it and adjusting its .size(). Then remove the ... from the vector. (It's an opportunistic optimization
545 * that eliminates one allocation and one seg copy.) Otherwise we must create a new large-enough seg and
546 * simply copy s1 and ... onto it; then replace s1 with the resulting segment and remove ... from the vector.
547 * - By our contract, we *are* allowed to invalidate m_serialization_segments elements -- both the `Blob`s
548 * themselves (essentially "handles" to data areas in memory) and the referred-to-thereby data areas themselves.
549 * However we are *not* allowed to invalidate the data area known as the header, which is
550 * the byte range [seg1.begin() - seg1.start(), seg1.begin()), where seg1 is m_serialization_segments[0].
551 * - Therefore: If seg1 is mentioned in split_segs, and its unused-capacity area is not large enough to
552 * enable the optimization in previous bullet point, then we must save seg1 somewhere -- to avoid invalidating
553 * the header area -- even as we replace it in m_serialization_segments with the new post-join segment Blob.
554 * For this purpose we use m_seg1_hdr_backup which shall simply keep the header (and remaining stuff, no
555 * longer used but cannot be deallocated due to being part of the header-containing buffer) until dtor
556 * destroys everything. */
557
558 const auto split_segs_it_rend = split_segs.rend();
559 for (auto split_segs_it = split_segs.rbegin();
560 split_segs_it != split_segs_it_rend;
561 ++split_segs_it)
562 {
563 const auto& split_seg = *split_segs_it;
564 const size_t start_idx = split_seg.m_start_idx;
565 const size_t n_cont_subsegs = split_seg.m_n_cont_subsegs;
566
567 /* m_s_s.size() changes on-the-fly, but we go in decreasing order of start_idx values (no, we don't check it;
568 * we trust the opposing side and check for correctness when we feel like it/decent effort), so the range
569 * check here is correct. The 1st check validates that a record is only included if a segment actually was
570 * split; plus we need not think about degenerate cases below as a result. Note the subtraction-form
571 * bounds checks: the naive `start_idx + n_cont_subsegs + 1 > .size()` could wrap around given garbage
572 * input values and pass. */
573 if ((n_cont_subsegs == 0) || (start_idx >= m_serialization_segments.size())
574 || (n_cont_subsegs > (m_serialization_segments.size() - 1 - start_idx)))
575 {
576 FLOW_LOG_WARNING("Heap_reader [" << *this << "]: "
577 "Split-segment record (start-index [" << start_idx << "] "
578 "(0-based, of [" << split_segs.size() << "], 1-based), "
579 "# continuation sub-segs [" << n_cont_subsegs << "]): "
580 "The latter value must be 1+ and not exceed (+ start_idx) # of input buffers "
581 "[" << m_serialization_segments.size() << "].");
582 *err_code = error::Code::S_DESERIALIZE_FAILED_REASSEMBLY_FAILED;
583 return {};
584 }
585 // else
586
587 const size_t end_idx = start_idx + n_cont_subsegs + 1; // n_cont_subsegs does *not* include start_idx-th one.
588 // (Cannot overflow: the range check above ensured end_idx <= m_serialization_segments.size().)
589
590 size_t cont_total_sz = 0;
591 for (size_t idx = start_idx + 1; idx != end_idx; ++idx)
592 {
593 cont_total_sz += m_serialization_segments[idx].size();
594 }
595
596 auto& subseg1 = m_serialization_segments[start_idx];
597 const bool first_seg = start_idx == 0; // I.e., whether `&subseg1 == &m_serialization_segments.front()`.
598
599 const auto unused_cap = static_cast<size_t>(subseg1.capacity() - subseg1.size() - subseg1.start());
600 if (unused_cap >= cont_total_sz)
601 {
602 // This is the case where subseg1's unused capacity can fit the remaining sub-segs' total bytes.
603 FLOW_LOG_TRACE("Heap_reader [" << *this << "]: "
604 "Split-segment record (start-index [" << start_idx << "] "
605 "(0-based, of [" << split_segs.size() << "], 1-based), "
606 "# continuation sub-segs [" << n_cont_subsegs << "]): "
607 "All [" << cont_total_sz << "] bytes across continuation sub-segs can fit into "
608 "unused capacity [" << unused_cap << "] of start-index-th sub-seg; copying their contents there "
609 "accordingly and deleting them.");
610
611 auto dest_it = subseg1.end();
612 subseg1.resize(subseg1.size() + cont_total_sz); // .start() left unchanged.
613 const auto cont_subseg_begin_it = m_serialization_segments.begin() + start_idx + 1;
614 const auto cont_subseg_end_it = m_serialization_segments.begin() + end_idx;
615 for (auto cont_subseg_it = cont_subseg_begin_it;
616 cont_subseg_it != cont_subseg_end_it;
617 (dest_it += cont_subseg_it->size()), ++cont_subseg_it)
618 {
619 subseg1.emplace_copy(dest_it, cont_subseg_it->const_buffer());
620 }
621 assert(dest_it == subseg1.end());
622
623 m_serialization_segments.erase(cont_subseg_begin_it, cont_subseg_end_it);
624
625 /* Per algorithm above, reminder: subseg1's original contents sit undisturbed; no need to worry about
626 * having to use m_seg1_hdr_backup, even if subseg1 is indeed m_serialization_segments.front(). It is
627 * still there (and always will be), just more bytes are tacked on at the end. */
628 } // if (unused_cap >= cont_total_sz) // subseg1 can fit all of subseg1 + continuation sub-segs.
629 else // if (subseg1 cannot fit all of subseg1 + continuation sub-segs)
630 {
631 /* This is the (probably likelier) case where subseg1 is no different than the others.
632 * Per algorithm above, reminders:
633 * - Mainly just make an all-new Blob combining subseg1 and the n_cont_subsegs other ones in that order.
634 * Then replace subseg1 with that resulting new Blob.
635 * - If subseg1 is .front() (<=> first_seg is true), then it must be saved in m_seg1_hdr_backup, so as to keep
636 * the header bytes alive where they are (and since buffer cannot be part-freed... all of it).
637 * So tactically we just use m_seg1_hdr_backup as bullet 1 result Blob. Then swap that guy with subseg1, and
638 * .erase() the other sub-segs from m_serialization_segments. If first_seg, we're done. Otherwise, also
639 * m_seg1_hdr_backup.make_zero(), since no need to keep ex-subseg1 bytes alive. That completes bullet 2.
640 *
641 * Note that we're going backwards; so first_seg is true (if ever) only in our very last iteration.
642 * Hence m_seg1_hdr_backup -- if it were ever non-.zero() in a previous iteration -- would have been
643 * de-alloc-ed before we got here. Hence these assert(). */
644 assert(m_seg1_hdr_backup.zero() && "Original state should be unallocated.");
645
646 m_seg1_hdr_backup.resize(subseg1.size() + cont_total_sz);
647 auto dest_it = m_seg1_hdr_backup.begin();
648
649 FLOW_LOG_TRACE("Heap_reader [" << *this << "]: "
650 "Split-segment record (start-index [" << start_idx << "] "
651 "(0-based, of [" << split_segs.size() << "], 1-based), "
652 "# continuation sub-segs [" << n_cont_subsegs << "]): "
653 "All [" << cont_total_sz << "] bytes across continuation sub-segs cannot fit into "
654 "unused capacity [" << unused_cap << "] of start-index-th sub-seg; "
655 "therefore creating new segment-blob of size [" << m_seg1_hdr_backup.size() << "], "
656 "copying sub-segs' contents there, and replacing sub-segments with the resulting blob. "
657 "Start-index-th sub-seg shall be saved elsewhere so as to keep frame-header alive? = "
658 "[" << first_seg << "].");
659
660 auto subseg_begin_it = m_serialization_segments.begin() + start_idx;
661 const auto subseg_end_it = m_serialization_segments.begin() + end_idx;
662 for (auto subseg_it = subseg_begin_it;
663 subseg_it != subseg_end_it;
664 (dest_it += subseg_it->size()), ++subseg_it)
665 {
666 m_seg1_hdr_backup.emplace_copy(dest_it, subseg_it->const_buffer());
667 }
668 assert(dest_it == m_seg1_hdr_backup.end());
669
670 swap(m_seg1_hdr_backup, subseg1);
671 if (!first_seg)
672 {
673 m_seg1_hdr_backup.make_zero();
674 }
675
676 m_serialization_segments.erase(++subseg_begin_it, subseg_end_it);
677 } // else // if (unused_cap < cont_total_sz) // subseg1 cannot fit all of subseg1 + continuation sub-segs.
678 } // for (split_seg in split_segs, backwards)
679 } // if (split_segs_or_null) // Usually false.
680
681 // m_serialization_segments won't change past this point for the lifetime of *this.
682
683 // Set up capnp ArrayPtr<ArrayPtr>. ArrayPtr is a ptr (to word) + size (in `word`s). The backing vector:
684 auto& capnp_segs = m_capnp_segments;
685 assert(capnp_segs.empty() && "m_capnp_segments should have been empty so far, pre-deserialization().");
686 capnp_segs.reserve(m_serialization_segments.size());
687
688 size_t idx = 0;
689 for (const auto& serialization_segment : m_serialization_segments)
690 {
691 const auto data_ptr = serialization_segment.const_data();
692 const auto seg_sz = serialization_segment.size();
693
694 if (((reinterpret_cast<uintptr_t>(data_ptr) % sizeof(word)) != 0) || ((seg_sz % sizeof(word)) != 0))
695 {
696 FLOW_LOG_WARNING("Heap_reader [" << *this << "]: "
697 "Serialization segment [" << idx << "] "
698 "(0-based, of [" << m_serialization_segments.size() << "], 1-based): "
699 "Heap buffer @[" << static_cast<const void*>(data_ptr) << "] sized [" << seg_sz << "]: "
700 "Starting pointer is not capnp-word-aligned, and/or size is not a capnp-word-multiple. "
701 "Bug? Misuse of Heap_reader? "
702 "Either is against the API use requirements; capnp would complain and fail.");
703 *err_code = error::Code::S_DESERIALIZE_FAILED_SEGMENT_MISALIGNED;
704 return {};
705 }
706 // else
707
708 FLOW_LOG_TRACE("Heap_reader [" << *this << "]: "
709 "Serialization segment [" << idx << "] "
710 "(0-based, of [" << m_serialization_segments.size() << "], 1-based): "
711 "Heap buffer @[" << static_cast<const void*>(data_ptr) << "] sized [" << seg_sz << "]: "
712 "Feeding into capnp deserialization engine.");
713 FLOW_LOG_DATA("Segment contents: "
714 "[\n" << buffers_dump_string(serialization_segment.const_buffer(), " ") << "].");
715
716 capnp_segs.emplace_back(reinterpret_cast<const word*>(data_ptr),
717 /* ^-- OK cast. We prefer dealing with bytes; capnp wants to deal with `word`s;
718 * we're giving it the right address, and it is aligned. The rest -- formal safety
719 * of further access in the segment -- is on capnp. */
720 seg_sz / sizeof(word)); // (An exact multiple: the size check above ensured it.)
721
722 /* Stats: To avoid another loop, we can accumulate these opportunistically. Could check `bool(m_stats)`, but
723 * that's slower overall, so just do it. */
724 m_alloc_sz += serialization_segment.capacity();
725 m_used_sz += seg_sz;
726
727 ++idx;
728 } // for (const auto& serialization_segment : m_serialization_segments)
729
730 /* Initialize the deserialization engine by giving it the pointers to/size of the backing segment blobs.
731 * It doesn't copy this array of pointers/sizes, so that array must stay alive, hence why capnp_segs is
732 * really m_capnp_segments. To be clear: not only must the blobs stay alive but so must the array referring
733 * to them. */
734 const Capnp_word_array_array_ptr capnp_segs_ptr{&(capnp_segs.front()), capnp_segs.size()};
735 m_engine = make_unique<Capnp_heap_engine>(capnp_segs_ptr, RDR_OPTIONS);
736
737 err_code->clear();
738
739 /* Stats. Past all early-exit error returns; m_engine is set (which indicates, in the stats context, that
740 * deserialization() happened and succeeded).
741 * (Context: If we are used by a Msg_in, that Msg_in can be emitted to the user by Channel.)
742 *
743 * Sample/increment everything here; the dtor decrements the gauges, partially based on
744 * m_alloc_sz and m_used_sz. */
745 if (m_stats)
746 {
747 update_hi_wmark(&m_stats->m_msgs_outstanding_hi_wmark,
748 fetch_add(&m_stats->m_msgs_outstanding, 1) + 1);
749 fetch_add(&m_stats->m_alloc_lifetime_sz, m_alloc_sz);
750 update_hi_wmark(&m_stats->m_alloc_outstanding_sz_hi_wmark,
751 fetch_add(&m_stats->m_alloc_outstanding_sz, m_alloc_sz) + m_alloc_sz);
752 update_hi_wmark(&m_stats->m_used_outstanding_sz_hi_wmark,
753 fetch_add(&m_stats->m_used_outstanding_sz, m_used_sz) + m_used_sz);
754 m_stats->m_histo_msg_alloc_sz.record_value(m_alloc_sz);
755 m_stats->m_histo_msg_used_sz.record_value(m_used_sz);
756 }
757
758 // And lastly set up the structured-accessor API object that'll traverse those blobs via that engine.
759 return m_engine->getRoot<Struct>();
760} // Heap_reader::deserialization()
