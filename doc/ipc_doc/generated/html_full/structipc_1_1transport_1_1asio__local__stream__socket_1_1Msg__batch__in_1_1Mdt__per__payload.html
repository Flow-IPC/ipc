template<typename Mutable_buffer_sequence_t , typename Msg_resource_t >
boost::asio::detail::buffer_sequence_adapter<util::Blob_mutable, Mutable_buffer_sequence> ipc::transport::asio_local_stream_socket::Msg_batch_in< Mutable_buffer_sequence_t, Msg_resource_t >::Mdt_per_payload::m_buf_seq_adapter

Efficient (via adapt-as-we-go technique) object that adapts the boost.asio portable Mutable_buffer_sequence (sequence of boost.asio util::Blob_mutable location/size structures) into the POSIX native iovec array containing the exact same information.

The implementation is cleverly specialized, so that depending on what concrete type Mutable_buffer_sequence actually is, the storage and access to the resulting iovecs is as performant as possible. In particular there are specializations for a single Blob_mutable; STL and Boost array<2> thereof; and (worst-case) variable-length things such as vector<Blob_mutable>. E.g., in Flow-IPC a major use-case is Native_socket_stream_msg_batch_in which in fact uses Mutable_buffer_sequence = array<Blob_mutable, 2>.

Defense of using an internal (detail) boost.asio class

Well, it's useful. We could roll "our own" by copy/pasting it instead, but in practice that's just busy-work. That said there is some risk of this changing under us with a newer Boost version; we accept this small risk.
