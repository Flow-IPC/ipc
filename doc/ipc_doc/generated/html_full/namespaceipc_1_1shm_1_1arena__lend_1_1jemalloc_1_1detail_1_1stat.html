Detailed Description

Stats-related sub-namespace within SHM-jemalloc's detail, for general organization (and ADL segregation if needed).

It contains the low-level substrate over jemalloc's mallctl() statistics API: thin, stateless helpers (epoch refresh, typed mallctl/mallctlbymib reads, MIB resolution) on which the higher-level bespoke SHM-jemalloc stat snapshots and the malloc_stats_print() dump are built.

Note
It is stateless... pretty much. Certain things do feature some initialize-once local statics. In all cases these represent, essentially, constants – just not ones available at compile-time.

bool ipc::shm::arena_lend::jemalloc::detail::stat::config_stats_enabled ( )

Returns whether the linked jemalloc was built with statistics support (its config.stats is true).

The value is read once – it is a compile-time constant within a given jemalloc build – and cached.

If this returns false, nearly every "stats.*" mallctl query yields ENOENT (a few page-count gauges, like stats.arenas.(i).pactive, remain available); accordingly the bespoke SHM-jemalloc stat snapshots shall, as a matter of policy, produce no real data (return defaults/sentinels) rather than partial results.

Computes, for the given jemalloc-arena, the cumulative bytes-ever-allocated and bytes-ever-deallocated (by summing each per-size-class cumulative op-count times that size-class's byte-size), and populates a by-size-class allocation-count histogram spanning all classes (jemalloc's small bins then its large lextents, concatenated) – all in one walk over the per-size-class counters.

jemalloc has no direct cumulative-bytes counter: hence the aforementioned derivation.

The histogram, with its request-range bucket bounds (see the by-size histogram member docs in arena_lend_stats.hpp), is (re)constructed fresh, then its buckets are overwritten from nmalloc (region allocations). So it is an ACCUMULATOR (with N per-bucket counts) in the flow::util::stat::Stat_type sense.

Pre-conditions: jemalloc-stats enabled within jemalloc; jemalloc-stats epoch refreshed.

Parameters
arena_idThe jemalloc-arena to read.
alloc_szOut: cumulative bytes allocated. Must not be null.
dealloc_szOut: cumulative bytes deallocated. Must not be null.
alloc_count_by_sizeOut: by-size-class cumulative alloc-count histogram (from nmalloc; overwritten). Must not be null.

◆ epoch_refresh()

uint64_t ipc::shm::arena_lend::jemalloc::detail::stat::epoch_refresh ( )

Refreshes jemalloc's statistics snapshot (writes mallctl("epoch")), so that subsequently-read "stats.*" values reflect the present; and returns the epoch of the resulting snapshot.

Background: jemalloc's stats snapshot and epoch

jemalloc does not compute a "stats.*" value when it is read; it serves every such read from one stored snapshot. A refresh (writing any value to epoch) copies every arena's current counters into that snapshot and increments a counter, the epoch. Merely reading epoch (epoch()) refreshes nothing. man page wording (the epoch entry): "If a value is passed in, refresh the data from which the <tt>mallctl*()</tt> functions report values, and increment the epoch. Return the current epoch. This is useful for detecting whether another thread caused a refresh."

There is one snapshot, and one epoch, for the entire process. So a refresh by anyone in the process (another Ipc_arena reading its stats; a stats dump; any code using jemalloc directly) replaces what everyone reads next. Each individual "stats.*" read is coherent; but a refresh between 2 reads of a batch makes the batch "torn": values from different moments. That can corrupt derived quantities (e.g., live-count = nmalloc - ndalloc can underflow). Conversely, with no refresh at all, reads are stale: frozen at the last snapshot, or all-zero if none was ever taken.

Recipe for a consistent batch: e = epoch_refresh(); read the batch; if epoch() != e, someone refreshed mid-batch, so set e = epoch() and read the batch again. There is no need to refresh again on such a retry: the other party's refresh already produced a snapshot at least as new as ours. Moreover, if we did refresh again, 2 concurrent readers could keep tearing each other's batches indefinitely.

Returns
The epoch of the snapshot just taken.

)

Resolves a mallctl name – which may contain integer components (e.g.

the 0s in stats.arenas.0.bins.0.nmalloc) – to its Management Information Base (MIB), enabling repeated reads via mallctl_read_mib() without repeated name lookups. Per the jemalloc MIB convention the integer components become fixed MIB slots that the caller may mutate per iteration (e.g. set the arena-index slot to each JAID).

Parameters
nameThe (NUL-terminated) mallctl name to resolve.
mibBuffer receiving the resolved MIB; must have capacity for at least *mib_len components.
mib_lenIn: the capacity of mib (the name's component count, e.g. 6 for stats.arenas.0.bins.0.nmalloc). Out: the actual resolved MIB length.
Returns
true on success; false on any mallctl error.

Reads a single scalar mallctl value, by name, into *val (using sizeof(T) as the value size).

Intended for one-off reads (init-time constants, scalars); for repeated reads of an indexed path prefer mallctl_name_to_mib() + mallctl_read_mib().

Template Parameters

valOn success, set to the read value; untouched on failure.
Returns
The mallctl() result: 0 on success; else the (errno-style) error (e.g. ENOENT if name is unavailable in this build).
