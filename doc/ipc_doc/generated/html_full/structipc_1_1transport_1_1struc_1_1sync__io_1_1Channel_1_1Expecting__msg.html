Detailed Description

template<typename Owned_channel_t, typename Msg_body_t, typename Builder_config_t, typename Reader_config_t>
struct ipc::transport::struc::sync_io::Channel< Owned_channel_t, Msg_body_t, Builder_config_t, Reader_config_t >::Expecting_msg

Policy for how to act upon receiving an expected message of one kind or another.

As of this writing there are two applicable scenarios:

  • receiving a response in-message that indicates its originating out-message is the message associated with this object in Expecting_response_map;
  • receiving an in-message whose top-level-union Msg_which_in enum equals the Msg_which_in associated with this object in Expecting_msg_map.

For the former see Expecting_response as well.

bool ipc::transport::struc::sync_io::Channel< Owned_channel_t, Msg_body_t, Builder_config_t, Reader_config_t >::Expecting_msg::m_one_expected

true if receiving the expected in-message means the expectation is satisfied; false if an undo_*() must be invoked to mark it satisfied.

This controls the mechanism by which an Expecting_msg is removed from the expected-messages map (Expecting_response_map, Expecting_msg_map), freeing the non-zero RAM (at least) resource involved.
